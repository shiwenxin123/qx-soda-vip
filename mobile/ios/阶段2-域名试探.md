# 阶段 2：逐个域名试探 pinning

**前提（已确认）**：MITM + 重写已通 —— httpbin 页面出现了 `MITM_AND_REWRITE_BOTH_WORK`。

由此反推：

> 之前把 `qishui.com` 加进 hostname 就断网 → **那是 pinning**，不是证书问题。
> 但这**不代表所有域名都 pin**。字节系常常只在关键业务域名上校验，
> 广告 / 日志 / 配置域名经常是裸的。

所以现在要做的是：**找出哪些域名没 pin**。一次只加一个，每次重启 VPN。

---

## 试探 1：广告域名（最安全）

坏了最多是广告加载失败，不影响听歌。

```
[rewrite_local]
^https?://ads5-normal-gl2\.zijieapi\.com/ url script-request-header https://cdn.jsdelivr.net/gh/shiwenxin123/qx-soda-vip@bc05327bf4bb99cca0ac0dac127df1513bef45e0/mobile/ios/qx_soda_ad_probe.js

[mitm]
hostname = ads5-normal-gl2.zijieapi.com
```

保存 → **重启 VPN** → 打开汽水，滑几屏让它请求广告 → 回到 QX 网络活动看这条：

| 现象 | 结论 |
|---|---|
| JS 计数 **+1**，或收到「汽水广告接口」通知 | ✅ **没 pin**，进试探 2 |
| 连接 `0B/0B`、`N/A`、JS 仍 0 | ❌ 这个域名也 pin，基本判死刑 |
| App 报网络错误 | 立刻删掉这行（说明连广告域名都 pin） |

---

## 试探 2：业务域名（仅试探 1 成功时做）

```
[mitm]
hostname = ads5-normal-gl2.zijieapi.com, api5-normal-c-lf.zijieapi.com
```

播放一首 VIP 歌（比如搜「林俊杰 江南」），看 `api5-normal-c-lf` 这条连接。

| 现象 | 结论 |
|---|---|
| 能解密，能看到 JSON | ✅ 把 `soda_vip_unlock.js` 的规则指到它，VIP 就有救 |
| `0B/0B` | ❌ 业务域名 pin 了 → 只能去广告，改不了会员态 |

如果 `api5-normal-c-lf` 不对，按 QX 网络活动里实际出现的业务域名替换
（常见形态：`api*-normal-*.zijieapi.com`、`*-luna.zijieapi.com`）。

---

## 结论分支

| 试探 1 | 试探 2 | 最终能力 |
|---|---|---|
| ✅ | ✅ | **完整可用**：VIP + 无损 + 去广告 |
| ✅ | ❌ | 只能去广告（改广告响应），VIP 无解 |
| ❌ | — | 全线 pinning，iOS 不越狱到此为止 |

## 附：中文乱码已修

你截图里 `MITM_SELFTEST` 的值是 `鈥� MITM 娑庡瓧...` —— 典型的
**UTF-8 字节被按 GBK 解码**。原因：QX 在 zh-CN 系统语言下会把脚本返回的
字符串按 GBK 编码写回响应。

已在所有脚本里加了强制头：

```js
const h = Object.assign({}, $response.headers);
h['Content-Type'] = 'application/json; charset=utf-8';
$done({ body: out, headers: h });
```

这个修复对主脚本也重要 —— 否则**歌名、歌手名、歌单名里的中文会全变乱码**。
（自检脚本的标记也改成了纯 ASCII：`MITM_AND_REWRITE_BOTH_WORK`。）
