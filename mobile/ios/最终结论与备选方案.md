# 最终结论：iOS 全线 pinning

## 证据链（按时间顺序，每一步都排除了一种可能）

| # | 测试 | 结果 | 排除了什么 |
|---|---|---|---|
| 1 | httpbin.org 走 MITM | 页面出现 `MITM_AND_REWRITE_BOTH_WORK` | ✅ 证书已信任、MITM 可用、重写可执行、CDN 可下载 |
| 2 | `qishui.com` 系列加 MITM | App 立刻断网，连接 `0B/0B` `N/A` | 排除"证书问题"，指向 pinning |
| 3 | `ads5-normal-gl2.zijieapi.com` 加 MITM | **网络正常，但 JS = 0** | 排除"只有关键域名 pin"的侥幸 |

第 3 步是关键：广告域名是最"不重要"的域名，如果连它都不让解密，
说明汽水用的是**全局证书校验**（cronet 内置 CA store + 指纹比对），
不是按域名选择性校验。

**结论：iOS 不越狱，无法通过流量改写实现 VIP 解锁或去广告。**

## 为什么 Mac 能、iOS 不能

| | Mac | iOS |
|---|---|---|
| 业务逻辑位置 | Electron 的明文 JS（`main.asar`） | 原生机器码（加密 IPA） |
| 可否改包 | 可以，改完 ad-hoc 重签 | 不可以（二进制加密） |
| 网络栈 | cronet，但 QX 只做代理不改包 | cronet + **全局证书 pinning** |
| 结果 | ✅ 已验证可用 | ❌ 流量层无解 |

## 备选方案（按可行性排序）

### A. 越狱 + Frida（唯一能真正解决的）

前提：设备可越狱（iOS ≤ 16.6.1 用 palera1n/dopamine 等，取决于芯片和版本）。

```bash
# 手机装 frida-server，电脑执行
frida -U -f com.soda.music -l mobile/android/frida_pinning_bypass.js
```

脚本已写好（`mobile/android/frida_pinning_bypass.js`，iOS 通用），做三件事：
Java 层 TrustManager（iOS 无效但无害）、BoringSSL `SSL_get_verify_result`→0、
`X509_verify_cert`→1、`SSL_CTX_set_verify` 清 `SSL_VERIFY_PEER` 位。

挂上之后再开 QX MITM，就能解密并改写。

> 风险：越狱本身降低系统安全性、可能影响银行/支付类 App、部分版本不稳定。

### B. TrollStore + 旧版 IPA（有版本窗口才有戏）

如果系统版本落在 TrollStore 支持范围（iOS 14.0–16.6.1 部分版本），
可以安装**旧版本 IPA**。老版本汽水可能还没上 pinning。

怎么试：
1. 找旧版 IPA（自己从旧设备提取 / 第三方存档站）
2. TrollStore 安装
3. 重复第 3 步测试：`ads5-normal-gl2.zijieapi.com` 加 MITM，看 JS 是否 +1

> 注意：旧版可能强制升级、接口不兼容。成功率未知，但成本低。

### C. 接受现状：分工使用（最省事）

- **iPhone**：正常听免费歌、刷推荐、看 MV（不去广告、不开 VIP）
- **Mac**：`/Applications/汽水音乐 VIP.app` 完整功能（已验证：无损 1541kbps、无弹窗、无 VIP 角标）

### D. 检查有没有 HTTP（非 HTTPS）接口 —— 最后一个便宜的机会

QX 改写 HTTP **不需要 MITM、不受 pinning 影响**。

在 QX 网络活动里翻一遍，找形如 `xxx.bytedance.com:80` / `xxx.qishui.com:80` 的请求
（你截图里 `paydns.weixin.qq.com:80` 就是 HTTP）。

如果广告配置或会员态接口有走 :80 的，就能直接改，无需解密。

```bash
# 判断方法：网络活动里看端口号
# :443 → HTTPS，被 pinning 挡
# :80  → HTTP，可以直接 rewrite
```

## 现在该清理什么

既然流量改写走不通，之前加的这些**可以全部删掉**，避免留隐患：

- `[mitm]` 里所有 `qishui.com` / `zijieapi.com` 条目 ← **必须删**，否则 App 会断网
- `[rewrite_local]` 里 httpbin 自检规则 ← 可删
- `[rewrite_local]` 里汽水相关规则 ← 可删（不会生效）
- `[filter_local]` 里广告 REJECT ← 可保留（无害，能挡掉一部分素材），但效果有限

**保留 `[filter_local]` 的广告 REJECT 是安全的**：它在连接层工作，不碰 TLS，
不会造成断网。只是广告位本身（数据内嵌在主接口里）去不掉。
