# 网页版路线 + 自动看广告换时长

## 好消息：网页版完全可用

你 02:04 的截图证明了两件事：

1. **网页版能正常打开**（"熟悉模式"、歌单、金币入口都在，不是下载引导页）
2. **网页版有激励体系**：
   - 「明日畅听 已领取」
   - 「第3天畅听 再看1个提前领」
   - 「看2个视频 享今日无损音质」

而且**浏览器没有证书 pinning** —— 这是 App 做不到的。

所以路线是：**网页版 + QX MITM + 自动领奖脚本**。

## 第一步：抓出奖励接口（必须先做）

不知道接口长什么样，任何自动化都是瞎猜。用这个探针脚本记录网页版的全部请求：

```
[rewrite_local]
^https?://[^/]*qishui\.com/ url script-request-header https://cdn.jsdelivr.net/gh/shiwenxin123/qx-soda-vip@cbf813e5d621199719377ee1e91a1a4de8afa460/mobile/ios/qx_web_probe.js

[mitm]
hostname = www.qishui.com, lf-luna.qishui.com, api.qishui.com, *.qishui.com
```

> 注意：这里加的是**网页版域名**，走浏览器栈，不会 pinning。
> 如果加了之后网页打不开，说明域名范围写太宽，逐个删。

**操作**：
1. Safari 打开网页版，登录
2. 手动看完 1 个广告
3. 点「解锁第3天畅听」
4. 回 QX → 日志，搜 `soda-web`

脚本会把命中的 URL 全记下来，存在本地键 `soda_web_log`。

## 第二步：识别三类接口

看完一遍后，日志里会出现三类：

| 类型 | 特征 | 用途 |
|---|---|---|
| 广告配置 | URL 含 `ad_config` / `media_ads`，返回 JSON 带 `duration` | 缩短时长 |
| 播放上报 | URL 含 `report` / `play_log` / `track` | 完成度校验 |
| **领奖** | URL 含 `reward` / `task` / `claim` / `receive`，**POST** | **自动领奖** |

**最关键的是第三类**。找到它，就能写自动脚本。

## 第三步：三种自动化方案

### 方案 A：直接调领奖接口（最简单，优先试）

如果「解锁第3天畅听」这个按钮背后是一个独立的 POST 请求，
那就不需要真的看广告 —— 直接调它就行。

抓到之后，用 QX 的 `$task.fetch` 定时重放：

```js
// 每天调用一次
const req = {
  url: 'https://api.qishui.com/luna/xxx/task/claim',   // ← 抓到的真实地址
  method: 'POST',
  headers: { 'Content-Type': 'application/json', Cookie: '...' },
  body: JSON.stringify({ task_id: 'watch_ad_3day' }),
};
$task.fetch(req).then(r => $notify('领奖', r.statusCode, r.body.slice(0,80)));
```

**成功率取决于**：服务端有没有校验「确实看完了广告」。
- 没校验 → 直接成功
- 校验了 ad_id / 播放时长 → 需要方案 B

### 方案 B：缩短广告时长

改写广告配置的 `duration` 字段为 0 或 1 秒。
播完 1 秒后，前端认为看完了，正常触发上报。

```
[rewrite_local]
^https?://[^/]*qishui\.com/.*(ad_config|media_ads) url script-response-body https://cdn.jsdelivr.net/gh/shiwenxin123/qx-soda-vip@<SHA>/mobile/ios/qx_soda_ad_auto.js
```

（`qx_soda_ad_auto.js` 已经实现这个逻辑，把 `duration`/`ad_duration`/`skip_time` 压到 0/1）

### 方案 C：伪造播放完成上报

如果 A 和 B 都失败，说明服务端校验播放进度。
那就抓「播放完成」的上报请求，复制它的 body（含 ad_id、进度、签名），按天重放。

难点：签名通常是时间戳+密钥算的，可能需要逆向网页 JS 找到签名算法。
网页版 JS 是明文的（`lf-luna.qishui.com/.../index-*.js`），可以搜签名函数。

## 关于「累计畅听天数」

截图里是「明日畅听」「第3天畅听」，说明是**按天累计**的机制：

- 每天看 N 个广告 → 解锁第 N 天
- 提前领 → 需要额外看广告

自动化节奏建议：
- 每天固定时间（比如早上 8 点）跑一次脚本
- 每次领完就停，别刷太猛
- **不要并发**，不要一天刷十几次 —— 这是最容易被风控的行为

## 与 App 的取舍

| | App | 网页版 |
|---|---|---|
| 广告 | 有，可看广告换时长 | 有，同样机制 |
| VIP 解锁（改流量） | ❌ pinning | ✅ 可以 |
| 功能完整度 | 100% | 约 60% |
| 自动化难度 | 高（pinning） | **低（浏览器无 pinning）** |

**结论**：如果目标是"自动看广告换时长"，网页版是唯一现实路径。
