# 关键区分：JS = 0 有两种原因，别混为一谈

## 你 01:32 的截图里没有广告域名

可见的连接只有：

```
s3plus.meituan.net:443        N/A  0B/0B    ← 美团，且在失败
v26-luna.douyinvod.com:443    DIRECT 241B  ← 音频 CDN，正常
github.com:443                全球加速 678B
v11-luna.douyinvod.com:443    DIRECT 0B/588B
```

**完全没有 `ads5-normal-gl2.zijieapi.com`，也没有任何 `qishui` / `zijieapi` 条目。**

所以「JS = 0」可能只是**那段时间 App 根本没请求广告域名**，
不能直接推出「广告域名也被 pin」。

## 两种可能，必须分清

| 网络活动里的表现 | 含义 | 下一步 |
|---|---|---|
| **搜不到 `zijieapi`** | App 没请求 → 测试无效 | 触发广告请求后重测 |
| **有，且 `0B/0B` `N/A` 红标** | MITM 被拒 = **pinning** | 判死刑 |
| **有，且有正常字节流动（如 9KB/5KB）** | hostname 没生效 | 检查域名拼写 / 是否保存 |

第二种和第三种的区别就是：**有没有数据流过**。
连接层成功但没解密 = hostname 没匹配上；连接失败 = 被 pin 了。

## 怎么确认（30 秒）

QX → 网络活动 → 顶部**搜索框** → 输入 `zijieapi`

- 搜到条目 → 点进去看字节数（0B 还是 几KB）
- 搜不到 → 说明 App 那会儿没请求，需要主动触发

## 怎么触发广告请求

1. 汽水 → 设置 → 清除缓存（如果有）
2. 或者：连续滑推荐流 20~30 屏，让它刷新到广告位
3. 或者：退出 App 再进（冷启动通常会拉一次广告配置）
4. 然后立刻回 QX 搜索 `zijieapi`

## 另一个可能：QUIC（UDP）

你截图顶部 **UDP 8**。字节系 App 大量用 QUIC(HTTP/3, UDP 443)。

**QX 无法 MITM UDP。** 如果广告/业务接口走 QUIC，那跟 pinning 是两回事 ——
即使没有 pinning，QX 也改不了，因为压根不经过它的 TLS 层。

判断方法：网络活动里看 `zijieapi` 是 `:443`(TCP) 还是 UDP 条目。
如果是 UDP，可以尝试在 QX 里屏蔽 UDP 443 逼它回落到 TCP：

```
[filter_local]
# 仅测试用：让 App 无法用 QUIC，回落到 TCP
# 副作用：可能变慢，某些功能异常
```

（这条不一定要加，先确认流量类型再说。）
